Core Primitive

Concept 1: Semaphores

A foundational synchronization tool formulated by Edsger W. Dijkstra in 1965 to resolve race conditions and enforce coordinated thread execution.

What is a Semaphore?

In Operating Systems, a semaphore is an integer variable accessed solely through two standard, indivisible (atomic) system operations: wait() and signal() (originally termed P for proberen, "to test", and V for verhogen, "to increment").

Binary Semaphores (Mutexes)

Value restricted to 0 or 1. Used to ensure mutual exclusion so that only one process executes the critical section at a given instant.

Counting Semaphores

Value ranges across an unrestricted positive integer domain. Represents the quantity of identical shared resources available (e.g., printer pool, database connections).

Unlike primitive spinlocks which waste CPU cycles in a busy-waiting loop, an OS-level blocking semaphore places stalled processes onto a dedicated FIFO Wait Queue and suspends them via sleep() until unblocked.

Semaphore Architecture & Atomic Operations Dijkstra Model
wait(S) / P(S)

Decrements semaphore count. If S < 0, calling process is added to the wait queue and suspended.

signal(S) / V(S)

Increments semaphore count. If S ≤ 0, removes and resumes a process from the FIFO waiting queue.

Concurrency Control

Concept 2: Process Synchronization

Managing concurrent threads to maintain data integrity when accessing shared memory, preventing race hazards, deadlocks, and starvation.

Standard Process Critical Section Model Mutual Exclusion

The Critical Section Problem

When multiple concurrent processes read and write shared data, the outcome depends on the order of execution. Without proper synchronization, a race condition arises, corrupting data integrity.

To achieve a robust synchronization protocol, any valid algorithm must satisfy three essential criteria:

1
Mutual Exclusion

If process Pi is executing in its critical section, no other process can execute in their critical sections simultaneously.

2
Progress

If no process is in its critical section and others wish to enter, only those not in their remainder section can participate in deciding who enters next.

3
Bounded Waiting

There exists a bound on the number of times other processes are allowed to enter after a process makes a request before its request is granted (prevents starvation).

Race Conditions

Occurs when unsynchronized threads interleave execution on shared memory (e.g., both reading counter = 5 simultaneously and writing back 6 instead of the correct sequential 7).

Deadlock

A stalemate condition where two or more processes are permanently blocked because each is holding a resource needed by another in a circular wait dependency.

Starvation

Indefinite postponement where a ready thread never gets scheduled because unfair scheduling or non-FIFO queues continually prioritize other incoming processes.

Implementation From Scratch

Real blocking semaphore implementation without using any built-in semaphore library. Includes a FIFO waiting queue and atomic thread block/unblock primitives.

/*
 * Semaphore Implementation From Scratch (C Language)
 * Operating Systems Project: Classical Dijkstra Blocking Semaphore
 * Implemented WITHOUT built-in semaphore libraries (sem_init, etc.)
 */

#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <stdatomic.h>

/* Process Control Block (PCB) Queue Node */
typedef struct ProcessNode {
    int pid;
    struct ProcessNode* next;
} ProcessNode;

/* FIFO Wait Queue structure for blocked processes */
typedef struct {
    ProcessNode* front;
    ProcessNode* rear;
} WaitQueue;

/* Semaphore Data Structure */
typedef struct {
    int value;                /* Available permits / negative wait counter */
    WaitQueue queue;          /* Dedicated FIFO queue of blocked processes */
    atomic_flag spinlock;     /* Hardware atomic flag protecting internal struct */
} CustomSemaphore;

/* Helper: Enqueue a blocked process */
void enqueue(WaitQueue* q, int pid) {
    ProcessNode* node = (ProcessNode*)malloc(sizeof(ProcessNode));
    node->pid = pid;
    node->next = NULL;
    if (q->rear == NULL) {
        q->front = q->rear = node;
        return;
    }
    q->rear->next = node;
    q->rear = node;
}

/* Helper: Dequeue an unblocked process */
int dequeue(WaitQueue* q) {
    if (q->front == NULL) return -1;
    ProcessNode* temp = q->front;
    int pid = temp->pid;
    q->front = q->front->next;
    if (q->front == NULL) q->rear = NULL;
    free(temp);
    return pid;
}

/* Initialize Semaphore */
void sem_init_custom(CustomSemaphore* sem, int initial_value) {
    sem->value = initial_value;
    sem->queue.front = NULL;
    sem->queue.rear = NULL;
    atomic_flag_clear(&sem->spinlock);
}

/* Classical Atomic wait() / P() / proberen Operation */
void sem_wait(CustomSemaphore* sem, int current_pid) {
    /* Acquire atomic spinlock solely to guard internal state updates */
    while (atomic_flag_test_and_set(&sem->spinlock));

    sem->value--;

    if (sem->value < 0) {
        /* Resource unavailable: place current process into wait queue */
        enqueue(&sem->queue, current_pid);
        printf("[PID %d] Resource busy (sem=%d). Enqueued into wait queue.\n", current_pid, sem->value);
        atomic_flag_clear(&sem->spinlock);
        
        /* OS kernel level block: suspends execution without busy waiting */
        os_block_process(current_pid);
    } else {
        atomic_flag_clear(&sem->spinlock);
        printf("[PID %d] Acquired semaphore (sem=%d). Entering Critical Section.\n", current_pid, sem->value);
    }
}

/* Classical Atomic signal() / V() / verhogen Operation */
void sem_signal(CustomSemaphore* sem) {
    while (atomic_flag_test_and_set(&sem->spinlock));

    sem->value++;

    if (sem->value <= 0) {
        /* Wake up one process from the wait queue in FIFO order */
        int woken_pid = dequeue(&sem->queue);
        atomic_flag_clear(&sem->spinlock);
        if (woken_pid != -1) {
            printf("[Signal] Waking up PID %d from wait queue.\n", woken_pid);
            os_wakeup_process(woken_pid);
        }
    } else {
        atomic_flag_clear(&sem->spinlock);
    }
}
"""
Semaphore Implementation From Scratch (Python)
Operating Systems Project: Blocking Semaphore with FIFO Queue
No built-in threading.Semaphore used.
"""

import collections
import threading
import time

class ScratchSemaphore:
    def __init__(self, initial_value: int = 1):
        # Integer value tracking resource availability
        self.value = initial_value
        # Real FIFO wait queue for blocked threads
        self.wait_queue = collections.deque()
        # Primitive lock used strictly to guard internal state modification
        self._guard = threading.Lock()

    def wait(self, process_id: str):
        """
        wait(P) operation:
        Decrements value. If negative, blocks the calling process on a custom Event.
        """
        with self._guard:
            self.value -= 1
            if self.value < 0:
                # Resource not free: allocate a thread condition event and block
                block_event = threading.Event()
                self.wait_queue.append((process_id, block_event))
                must_block = True
            else:
                must_block = False

        if must_block:
            print(f"[{process_id}] Resource busy (sem={self.value}). Placed in wait queue.")
            # Suspension: Thread yields CPU and sleeps until signal() fires
            block_event.wait()
            print(f"[{process_id}] Woken up! Resuming and entering Critical Section.")
        else:
            print(f"[{process_id}] Permit granted immediately (sem={self.value}).")

    def signal(self):
        """
        signal(V) operation:
        Increments value. If value <= 0, releases the oldest blocked process in FIFO order.
        """
        with self._guard:
            self.value += 1
            if self.value <= 0 and len(self.wait_queue) > 0:
                process_id, block_event = self.wait_queue.popleft()
                print(f"[Signal] Unblocking {process_id} from wait queue.")
                block_event.set() # Wakes up waiting thread
Key Mechanism: The internal spinlock / guard is held only for microseconds to modify value and update the wait_queue. The calling process is suspended using OS descheduling (block() / Event.wait()) rather than a CPU-burning spin loop.

Producer-Consumer Synchronization

Solving the classical Bounded Buffer problem using three semaphores: mutex for mutual exclusion, empty for empty slot tracking, and full for filled slot count.

The Bounded-Buffer Problem

A producer process generates items and puts them into a shared buffer of size N = 5. A consumer process removes items from the buffer.

To prevent buffer overflow (producing when full) and buffer underflow (consuming when empty), three semaphores coordinate the processes:

S1
mutex = 1 (Binary Semaphore)

Guarantees mutual exclusion so producer and consumer cannot access the buffer array simultaneously.

S2
empty = 5 (Counting Semaphore)

Counts free slots. Initialized to N. Producer decrements with wait(empty).

S3
full = 0 (Counting Semaphore)

Counts occupied slots. Initialized to 0. Consumer decrements with wait(full).

Project Summary & Takeaways

Semaphores remain one of the most elegant, versatile primitives in computer engineering. Through this project, we demonstrated that hardware-level spinlocks can be elevated into non-busy-waiting blocking semaphores via kernel-managed wait queues.

  • Mutual Exclusion: Binary semaphores effectively resolve the critical section problem without CPU waste.
  • Race Condition Prevention: Disabling the semaphore in the simulator confirmed immediate data corruption in shared memory.
  • Bounded Buffer Solution: The triple-semaphore approach coordinates producers and consumers while completely eliminating deadlock.
